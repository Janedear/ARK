What becomes possible

Five capabilities that emerge at scale

01

Real-time resource routing

When enough households post what they have — food, fuel, generators, medication — ARK can route requests to the nearest supply automatically. No central database. No internet. Just neighbors finding neighbors.

02

Hospital coordination

Hubs at medical facilities broadcast bed availability, blood inventory, and triage capacity. Responders see the full picture before moving a patient. No phone trees. No waiting on hold.

03

Missing person relay

A message posted to one hub propagates to every connected hub in range. A family separated in an evacuation can find each other without cell service, without an app store, without anything except ARK already installed.

04

Community accountability

Every message is cryptographically signed. Official alerts cannot be spoofed. Community reports cannot be forged as official alerts. The chain of trust is built into the protocol — no verification service required.

05

Offline-first resilience

ARK does not degrade gracefully — it was designed from the start for the worst case. The network that forms when the grid goes down is the same network that runs when it's up. No separate "emergency mode." No switching. It just works.

Local Hub

Your neighborhood's
communication center

The ARK Local Hub is a lightweight server you run on a laptop or Raspberry Pi. Everyone on your Wi-Fi network can connect. No internet needed. When your neighborhood's hub is running, it becomes the backbone of local coordination.

  • Zero npm dependencies: pure Node.js 18+
  • Runs on Raspberry Pi 3B+ or better
  • 10 message channels + resources + households
  • Hospital coordination (triage, beds, blood inventory)
  • Responder coordination (ICS/NIMS roles)
  • File library with download portal
  • Real-time Server-Sent Events
  • Hub-to-hub sync (mutual aid broadcast)
  • Cryptographic audit log, tamper-evident
  • Three-tier auth: public / community / trusted

Cryptographic signing · P-256 ECDSA · Three-tier auth · Offline-first · Zero dependencies
Wire format
# Compact text form (radio / SMS / QR)
ARK|<channel>|<alias>|<text>

Signed envelope    ECDSA P-256, SHA-256 digest
Signing key        SubtleCrypto.generateKey, P-256 JWK; hub key stored 0600, never leaves the device
Signature          base64url (86 chars) in packet.signature
Packet id          sha256(canonical bytes); hub deduplicates by id
Replay window      issued_at / expires_at checked; max lifetime 72h, future skew ≤ 5 min
Example signed packet
{
  "v": 1,
  "kind": "message",
  "channel": "medical",
  "alias": "Nurse-Maple-St",
  "text": "Insulin available at 42 Maple, fridge powered by generator",
  "ref": "",
  "issued_at": "2026-11-15T14:02:11.000Z",
  "expires_at": "2026-11-16T14:02:11.000Z",
  "public_key": { "kty": "EC", "crv": "P-256", "x": "f83OJ3D2xF1Bg8vub9tLe1gHMzV76e8Tus9uPHvRVEU", "y": "x_FEzRu9m36HLN_tue659LNpXW6pCyStikYjKIWI5a0" },
  "id": "9c1f…e04b",        // sha256 of the canonical fields above
  "signature": "MEUCIQ…base64url"
}

The hub recomputes the id from a fixed field order and verifies the signature against the key the packet carries. Any edit in transit changes the fingerprint and the packet is rejected.

Tier 1 — Public (read-only)
  GET  /api/messages, GET /api/bundle        # no credentials

Tier 2 — Community (rate-limited writes)
  POST /api/post                            # 20 req / 10 min per IP
  auto-stamped: provenance = "community_report"

Tier 3 — Trusted (hub operations)
  POST /api/bundle, POST /api/peer-announce, all /api/admin/*
  requires: Authorization: Bearer <hubKey>
  hubKey = sha256(sha256(passphrase))

Hub-to-hub sync   X-ARK-Hub-Key: <hubKey>
QR pairing        key = sha256(hubKey)   # scanning the QR does not reveal the Bearer token
Startup gates
# Dev mode: ARK_HUB_PASSPHRASE unset → all endpoints open (never deploy like this)
# Production gate: NODE_ENV=production without a passphrase → hub refuses to start
[ARK] STARTUP REFUSED: ARK_HUB_PASSPHRASE must be set in NODE_ENV=production.

Every message carries a provenance label so readers can weigh it. Labels are assigned by the hub, never trusted from the sender.
